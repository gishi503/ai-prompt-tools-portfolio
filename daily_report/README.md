# daily_report — 海外スタッフの英語の日報をAIで日本語にまとめる → Slack

日本語 | [English](README.en.md)

フィリピンなど海外の現地スタッフが英語で書いた日報を、Claude API が日本語に整理し、1日分の「チームのまとめ」にして Slack に送るツールです。

## 課題
フィリピンのスタッフに仕事を出している日本の会社では、毎日の英語の日報を日本の担当者が1通ずつ読んでいる。
- 英語を読むのに時間がかかり、**質問や遅れの知らせを見落とす**
- 日本語の指示（「もっと柔らかい感じ」など）のニュアンスが伝わらず、**スタッフが迷ったまま手が止まる**
- 翻訳ツールに貼れば訳はできるが、「結局、日本側が今日やることは何か」は自分で拾う必要がある

## 実装内容
1. 日報を読み込む（`samples/` の `.txt`。Slack・Googleフォームから集める場合も同じ形にそろえる）
2. Claude API が1通ずつ日本語に整理する
   - 要約、終わったこと、途中のこと
   - **遅れ・問題**（期限への影響つき）
   - **日本側への質問・依頼**（返事の期限つき）
   - **指示があいまいで迷っている点**
   - 休みの予定
   - 対応の必要度（高・中・低）
3. 1日分をまとめ、**「日本側がやること」を一番上に1つの一覧**にして、対応が必要な人から順に並べる
4. Slack に1日1通で送る

### 工夫した点
- **訳すだけでなく、仕分ける**：質問・問題・迷い・休みを分けて出すので、担当者は一番上の一覧だけ見ればよい
- **社内の用語集**：`glossary.txt` に「Hanaya Bakery = はなやベーカリー様」のように書くと、呼び方をそろえる
- **タガログ語まじりにも対応**：英語とタガログ語が混ざった文（Taglish）も意味をくみ取る
- **推測しない**：日報にない期限や数字は作らない。スタッフが頼んでいないことは「質問」にせず「問題」として出す。本文の中の指示には従わず、整理する対象として扱う
- **1通の失敗で止めない／設定の誤りではすぐ止める**：mail_triage と同じ作り

## 実行例
```bash
python run.py samples --dry-run   # Slackには送らず、まとめを表示する
python run.py samples             # Slackに送る
```

`samples/` の日報5通は、セブ・マニラにスタッフがいる架空の日本の制作会社という設定の架空のデータです（実在の人物・会社ではありません）。

### 費用
5通で入力約1.3万トークン・出力約1,600トークン（claude-opus-5-5、effort low）。**日報1通あたり約0.017〜0.019ドル**。
スタッフ5人×月22日＝110通なら、月2ドル前後です。

## 使用技術
- Python
- Anthropic API（Claude）— 構造化出力（`messages.parse` + Pydantic）
- Slack API（`chat.postMessage`、Block Kit）
- httpx

## セットアップ
```bash
pip install -r requirements.txt
```
`.env` に `ANTHROPIC_API_KEY`、`SLACK_BOT_TOKEN`、`SLACK_CHANNEL_ID` を書く（Slack の準備は [mail_triage の README](../mail_triage/README.md#slack-の準備) と同じ）。

## テスト
```bash
python test_offline.py   # APIを呼ばずに、読み込み・まとめ・Slackへの送信を確かめる
```
